# 实验二 AI 辅助设计使用记录

此文件记录真实协作过程，供后续报告引用与人工补充。AI 编写的初稿和修改不标注为人工完成。

## 2026-11-02：需求解读、图种选择与工具准备

- 使用场景：理解实验二要求，选择适合校园二手交易系统的四种 UML 图，比较 Java 与 C++，准备 PlantUML 工具。
- 生成结果：建议类图、组件图、状态图、时序图；建议 Java；下载 IntelliJ IDEA 的 plantuml4idea 官方插件安装包。
- 用户明确决定：提供今年新版要求，纠正旧附件中的报告 AI 使用限制和截止日期；决定使用 Java、从类图开始；随后反馈插件已安装。
- AI 输出的局限：最初按旧附件解释“报告禁止 AI 辅助”，新版实际允许；因此以用户后来提供的 2026 年要求为准。工具下载经历超时，最后从官方 CDN 分段获取并检查 ZIP 完整性。
- 修改优化结果：采用新版要求、Java 和本地 PlantUML；工作分支为 `UML-and-UI`。
- 人工体验与优缺点评价：待用户补充，不由 AI 冒充。

## 2026-11-02：UML 类图 AI 初稿 v0.1

- 使用场景：用户要求根据实验一需求生成类图初稿，明确类的划分、继承、实体属性，并考虑低耦合与高内聚。
- 输入：`requirements.md` 的 REQ-001—REQ-028，以及用户关于 Java 和建模质量的要求。
- 生成结果：`UML/` 中的总览类图、六张领域属性详图、一张服务接口详图、复用模型片段及 `类图设计说明.md`。
- AI 提出的设计：角色关联代替买卖身份继承；线上/线下支付继承共同抽象父类；账号/商品限制继承共同抽象父类；跨域保存 UUID，通过服务与仓储协调。
- AI 自检与调整：将初稿编写过程中的通用持久化接口细化为按业务划分的仓储，保留独立事务边界；核对快照、取消例外、资金结算、售后验收、退回重审和幂等约束；执行 PlantUML 语法检查、渲染和图片布局检查。
- 优点分析（AI 自评，供人工核对）：实体按业务职责组织，关键关系与属性可追溯到需求；源文件复用，便于 Git 对比；避免用单一状态混淆订单、付款和退款。
- 局限分析（AI 自评，供人工核对）：完整需求带来较多实体；总览隐藏成员，需结合属性详图阅读；部分仓储和服务签名仍为设计级概览；一次申请一次最终验收等初稿选择需用户确认；图不能证明真实并发、权限或支付实现正确。
- 用户检查意见：尚未收到，待用户审查后如实追加。
- 人工修改或人工意见驱动的优化结果：尚未发生，不能把本次 AI 自检记作人工修改。
- 版本追踪：本次提交作为 AI 初稿基线；后续用户审查意见和修改应形成独立提交。

## 后续工作流讨论素材（待人工评价）

候选流程：人工明确范围与约束 → AI 生成可追溯初稿 → 自动检查语法与渲染 → 人工逐项核对需求与设计取舍 → AI 按明确意见修改 → Git 保留差异 → 人工验收。
这只是待评价的工作流，不是用户的个人体验结论。是否能把人的工作缩减到检查校对，需要结合后续实际审查中发现的问题、决策和修改量来判断。
